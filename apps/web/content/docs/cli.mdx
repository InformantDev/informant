---
title: CLI reference
description: Operate workers, trigger runs, and inspect build history.
---

```text
informant setup                        Create the GitHub App and configure this machine
informant init                         Create .informant/ and register the origin repository
informant repo add [owner/repo]        Register a repository; defaults to the current Git remote
informant repo list                    List repositories handled by this machine
informant repo remove [owner/repo]     Stop handling a repository
informant serve                        Poll every registered repository continuously
informant serve --once                 Poll every registered repository once
informant run --local --ref HEAD       Locally run every job for a commit
informant run --local --job test       Locally run one job and the jobs it needs
informant run --local --job test --job lint
                                       Locally run multiple selected jobs
informant trigger --ref HEAD           Trigger jobs and report them to the commit
informant trigger --job test           Trigger one reported job and its dependencies
informant image prepare                Prepare configured Tart VM job images
informant image list                   List Informant-prepared Tart images
informant image prune                  Delete unused prepared runtime images
informant cache path                   Print the persistent job cache directory
informant cache prune                  Delete keyed caches while preserving shared caches
informant cache clear                  Delete all persistent job caches
informant startup enable               Start the worker now and automatically at login
informant startup disable              Stop and remove the automatic startup worker
informant hook install                 Install the push-accelerating pre-push hook
informant hook uninstall               Remove Informant from the pre-push hook
informant builds                       List builds currently running on this machine
informant builds --all                 List recent build history
informant logs [<build-id>]             Tail a build's logs or select a running job
informant update                        Update with Homebrew and restart a running worker
informant storage                      Show Informant disk usage and available space
informant doctor                       Verify host tools, GitHub auth, and disk space
```

`informant setup` stores GitHub App credentials automatically. Environment variables are optional
overrides for headless provisioning and external secret managers. The separate `gh` login is used to
clone repositories. See [GitHub App credentials](/docs/github-app) for details.

Registered repositories are machine-local and persist in `~/.config/informant/config.json`. Set
`INFORMANT_CONFIG_FILE` to use a different location. A running worker automatically starts polling
newly registered repositories and stops polling repositories after they are removed.

Local build records live under `~/.local/share/informant`; set `INFORMANT_DATA_DIR` to move them.
The build list shows running jobs and links each build to its GitHub pull request or commit. Pass
`--all` to show the 100 most recently updated local records. Retained logs contain at most the final
1 MiB of stdout and 1 MiB of stderr from each command. Run `informant logs` interactively to select
and follow a currently running job, or pass a build ID to follow its combined log directly. Informant
timestamps job lifecycle events while leaving command output unchanged.

`informant storage` breaks down the data directory into caches, builds and logs, and other files. It
also includes Informant-owned Tart VM images, counts prepared Apple Container images, reports free
host capacity, and shows runtime-wide Apple Container image usage when that runtime is available.
Container layers are shared, so their physical usage cannot be attributed to Informant alone; the
command keeps that shared total separate and labels it runtime-wide. The report ends with cleanup
commands and notes when a command can affect images outside Informant.

The worker runs housekeeping at startup and whenever all builds become idle. It keeps at least the
100 newest build records, removes additional records after 30 days, globally expires old keyed-cache
versions, caps keyed caches at 20 GB, and removes caches and prepared images whose repository or job
is no longer configured. Cleanup never runs while a build is active. Shared caches are retained unless
the host is below its free-space target; under pressure, Informant removes old build history, keyed
caches, and finally shared caches until the target is recovered.

These environment variables tune the policy:

| Variable | Default | Purpose |
| --- | ---: | --- |
| `INFORMANT_BUILD_RETENTION_DAYS` | `30` | Age after which build records beyond the history limit can be removed |
| `INFORMANT_BUILD_HISTORY_LIMIT` | `100` | Build records kept during routine cleanup |
| `INFORMANT_PRESSURE_BUILD_HISTORY_LIMIT` | `20` | Build records protected when disk space is low |
| `INFORMANT_KEYED_CACHE_MAX_GB` | `20` | Maximum allocated size of persistent keyed caches |
| `INFORMANT_MIN_FREE_SPACE_GB` | `25` | Minimum host free-space target |
| `INFORMANT_MIN_FREE_SPACE_PERCENT` | `10` | Minimum host free-space percentage target |

`informant doctor` uses the same configurable free-space target for warnings. It fails the disk-space
check when less than 10 GB or 5% remains, since builds and runtime image preparation may no longer
have enough working space.

`informant startup enable` installs and immediately loads a per-user macOS LaunchAgent or Linux
systemd user service. The worker
restarts if it exits and starts again when you log in. Its output is written to `worker.stdout.log`
and `worker.stderr.log` in the Informant data directory. Run `informant startup enable` again after
changing any `INFORMANT_*` environment-variable overrides so the service captures the new values.

`informant update` upgrades `informant-ci/tap/informant` with Homebrew. If the startup LaunchAgent was
already loaded, the command restarts it after the upgrade without rewriting its captured environment.
It does not start a worker that was stopped or never enabled.

`informant run --local` accepts repeatable `--job` flags as well as comma-separated job names. Only
selected jobs and their transitive `needs` dependencies run. Omit `--job` to run the complete job
graph. Local runs bypass job filters and write only local build history and logs; they do not create
GitHub checks.

`informant trigger` accepts the same selection flags, applies job filters, and reports the build and
job checks on the selected commit. The push-acceleration hook uses this path. During migration,
`informant run` retains its previous reported-trigger behavior, including the optional
`--wait-for-github` flag used by previously installed hooks. New scripts should use either
`informant trigger` or `informant run --local` explicitly.

Completed builds can also be re-run from GitHub. Open the commit or pull request checks, select the
Informant check, and click **Re-run**. GitHub marks the Check Suite as queued, and the next Informant
poll lets one eligible machine claim the new attempt. No webhook endpoint is required.
