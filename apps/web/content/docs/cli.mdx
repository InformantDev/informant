```text
informant setup                        Create the GitHub App and configure this machine
informant init                         Create .informant/ and register the origin repository
informant repo add [owner/repo]        Register a repository; defaults to the current Git remote
informant repo list                    List repositories handled by this machine
informant repo remove [owner/repo]     Stop handling a repository
informant mount allow <name> <file>    Allow jobs to request a host file by name
informant mount list                   List allowed host file mounts
informant mount remove <name>          Remove a host file from the allowlist
informant serve                        Run webhook networking or the polling fallback
informant serve --once                 Poll every registered repository once
informant run --local --ref HEAD       Locally run every job for a commit
informant run --local --job test       Locally run one job and the jobs it needs
informant run --local --job test --job lint
                                       Locally run multiple selected jobs
informant trigger --ref HEAD           Trigger jobs and report them to the commit
informant trigger --job test           Trigger one reported job and its dependencies
informant image prepare                Prepare configured Tart VM job images
informant image list                   List Informant-prepared Tart images
informant image prune                  Delete unused prepared runtime images
informant cache path                   Print the persistent job cache directory
informant cache prune                  Delete keyed caches while preserving shared caches
informant cache clear                  Delete all persistent job caches
informant startup enable               Start the worker now and automatically at login
informant startup disable              Stop and remove the automatic startup worker
informant tailscale enable --lead [--webhook-ready]
                                        Configure Funnel and the GitHub App webhook
informant tailscale enable --worker --token <token>
                                        Receive tailnet jobs without polling GitHub
informant tailscale status             Show Funnel state and discovered workers
informant tailscale disable            Disable networking and restore polling
informant auto-update enable           Check for and install new Informant releases automatically
informant auto-update disable          Disable automatic release checks
informant hook install                 Install the push-accelerating pre-push hook
informant hook uninstall               Remove Informant from the pre-push hook
informant builds                       List builds running across tailnet workers
informant builds --all                 List recent cross-worker build history
informant builds cancel <build-id>     Cancel a running local build
informant builds cancel <build-id> --job test
                                       Cancel one queued or running local job
informant logs [<build-id>]             Tail a build's logs or select a running job
informant update                        Install a newer release and restart a running worker
informant storage                      Show Informant disk usage and available space
informant doctor                       Verify host tools, GitHub auth, and disk space
```

`informant setup` stores GitHub App credentials automatically. Environment variables are optional
overrides for headless provisioning and external secret managers. The separate `gh` login is used to
clone repositories. See [GitHub App credentials](/docs/github-app) for details.

Registered repositories are machine-local and persist in `~/.config/informant/config.json`. Set
`INFORMANT_CONFIG_FILE` to use a different location. A running polling worker automatically starts
serving newly registered repositories and stops after they are removed.

## Tailscale networking

Install and connect Tailscale before `informant setup` to avoid continuous GitHub polling. On macOS,
Informant finds both a `tailscale` command on `PATH` and the CLI embedded at
`/Applications/Tailscale.app/Contents/MacOS/Tailscale`. A newly created App makes this machine the
lead, enables Funnel, stores GitHub's webhook secret in the mode-`600` machine configuration, and
subscribes to push, pull request, issue comment, and check suite events. Connecting an existing App
keeps polling enabled; switch it to worker mode explicitly only after a lead is running.

Use the explicit commands to change roles later:

```bash
informant tailscale enable --lead --webhook-ready
informant tailscale enable --worker --token <token-shown-by-lead>
informant tailscale status
informant startup enable # restart after changing the role
```

`tailscale disable` gracefully restarts an active managed worker so polling resumes immediately. If
the worker is running in a terminal or another supervisor, polling begins the next time that process
starts.

Lead enablement prints direct **General** and **Permissions & events** settings links for every
locally configured GitHub App, requires confirmation that each webhook is active, verifies that it
subscribes to **Push**, **Pull request**, **Issue comment**, and **Check suite**, then updates its
Funnel URL. When Tailscale requires tailnet-owner approval for Funnel, Informant opens the approval
page and waits up to two minutes instead of hanging silently. GitHub does not expose an API for
changing an existing App's activation or
event subscriptions, so lead enablement stops with instructions instead of disabling polling when
one is missing. The lead prints a worker token; supply that token
when explicitly enabling each worker. All private health, dispatch, build, and log requests require
this shared token in addition to traveling over Tailscale. The public Funnel forwards to a separate
loopback port containing only the HMAC-verified GitHub endpoint.

Local build records live under `~/.local/share/informant`; set `INFORMANT_DATA_DIR` to move them.
The build list shows running jobs and links each build to its GitHub pull request or commit. Pass
`--all` to merge the 100 most recently updated records reported by each reachable worker. Retained logs contain at most the final
1 MiB of stdout and 1 MiB of stderr from each command. Run `informant logs` interactively to select
and follow a currently running local job, or pass a local or remote build ID to tail its combined log
directly. Informant
timestamps job lifecycle events while leaving command output unchanged.

In the interactive build list, select a running build or a queued/running job and press `c` to cancel
it after confirmation. Scripts can use `informant builds cancel <build-id>`, with `--job <name>` to
cancel only one job. Cancelling a job leaves independent jobs running; jobs that depend on it are
skipped. Informant stops the selected process, marks its local record and GitHub check as cancelled,
and then completes the aggregate check.

`informant storage` breaks down the data directory into caches, builds and logs, and other files. It
also includes Informant-owned Tart VM images, counts prepared images in Apple Container or rootless
Podman, reports free host capacity, and shows runtime-wide container image usage when available.
Container layers are shared, so their physical usage cannot be attributed to Informant alone; the
command keeps that shared total separate and labels it runtime-wide. Informant's prune command remains
scoped to Informant prepared images. It does not suggest or run a global Podman prune, which could
affect unrelated images or interrupted Buildah work owned by the same user.

`informant doctor` names the selected backend and verifies Apple Container readiness on macOS or
rootless Podman health on Linux. Missing, unhealthy, or rootful Podman prevents the worker from
claiming `runs_on = ["container"]` jobs; host-only jobs remain available. `informant setup` can install
Podman from Debian/Ubuntu or Fedora/RHEL packages and smoke tests `docker.io/oven/bun:1`. It never uses
curl-to-shell or starts a systemd service.

The worker runs housekeeping at startup and whenever all builds become idle. It keeps at least the
100 newest build records, removes additional records after 30 days, globally expires old keyed-cache
versions, caps keyed caches at 20 GB, and removes caches and prepared images whose repository or job
is no longer configured. Cleanup never runs while a build is active. Shared caches are retained unless
the host is below its free-space target; under pressure, Informant removes old build history, keyed
caches, and finally shared caches until the target is recovered.

These environment variables tune the policy:

| Variable | Default | Purpose |
| --- | ---: | --- |
| `INFORMANT_BUILD_RETENTION_DAYS` | `30` | Age after which build records beyond the history limit can be removed |
| `INFORMANT_BUILD_HISTORY_LIMIT` | `100` | Build records kept during routine cleanup |
| `INFORMANT_PRESSURE_BUILD_HISTORY_LIMIT` | `20` | Build records protected when disk space is low |
| `INFORMANT_KEYED_CACHE_MAX_GB` | `20` | Maximum allocated size of persistent keyed caches |
| `INFORMANT_MIN_FREE_SPACE_GB` | `25` | Minimum host free-space target |
| `INFORMANT_MIN_FREE_SPACE_PERCENT` | `10` | Minimum host free-space percentage target |

`informant doctor` uses the same configurable free-space target for warnings. It fails the disk-space
check when less than 10 GB or 5% remains, since builds and runtime image preparation may no longer
have enough working space.

`informant startup enable` installs and immediately loads a per-user macOS LaunchAgent or Linux
systemd user service. It therefore requires a working systemd user manager on Linux. On hosts without
one, run `informant serve` in the foreground or configure it in the host's existing supervisor; Podman
does not need a daemon or systemd unit. The managed worker
restarts if it exits and starts again when you log in. Its output is written to `worker.stdout.log`
and `worker.stderr.log` in the Informant data directory. Run `informant startup enable` again after
changing any `INFORMANT_*` environment-variable overrides so the service captures the new values.

`informant update` checks GitHub's latest stable release before making changes. On macOS it upgrades
`informantdev/tap/informant` with Homebrew. Linux Homebrew installations use that same formula
upgrade path. For standalone Linux installations, it downloads the matching release binary, verifies
it against the release's `SHA256SUMS`, and atomically replaces the installed executable; the
executable and its parent directory must be writable by the worker user. If the startup worker was
already running, the command gracefully stops it and waits for launchd or systemd to start the new
version. It does not start a worker that was stopped or never enabled.

The first-run automatic-update choice in `informant setup` installs a launchd agent or persistent
systemd user timer that performs the same version check every six hours. The updater only installs a
strictly newer stable version. Change the setup choice later with `informant auto-update enable` or
`informant auto-update disable`; Linux requires a running systemd user manager.

`informant run --local` accepts repeatable `--job` flags as well as comma-separated job names. Only
selected jobs and their transitive `needs` dependencies run. Omit `--job` to run the complete job
graph. Local runs bypass job filters and write only local build history and logs; they do not create
GitHub checks.

`informant trigger` accepts the same selection flags, applies job filters, and reports the build and
job checks on the selected commit. The push-acceleration hook uses this path. During migration,
`informant run` retains its previous reported-trigger behavior, including the optional
`--wait-for-github` flag used by previously installed hooks. New scripts should use either
`informant trigger` or `informant run --local` explicitly.

Completed builds can also be re-run from GitHub. Open the commit or pull request checks, select the
Informant check, and click **Re-run**. GitHub marks the Check Suite as queued; the App's webhook
notifies network workers immediately, or the next polling cycle finds it when networking is disabled.
