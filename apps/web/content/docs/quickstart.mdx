## Requirements

- Apple Silicon macOS 13 or newer; Apple Container jobs require macOS 26 or newer
- Or Debian/Ubuntu/Fedora/RHEL Linux with rootless Podman and cgroups v2
- Git and GitHub CLI; Homebrew for the documented macOS installation

## Install Informant

On macOS, install the standalone Informant binary from its Homebrew tap and GitHub CLI:

```bash
brew install informantdev/tap/informant
brew install gh
gh auth login
informant --version
```

On Linux, install Informant separately before running setup. The repository currently provides a
standalone binary build path from a source checkout with Bun installed:

```bash
bun install
bun run --cwd apps/informant build:binary
mkdir -p "$HOME/.local/bin"
install -m 0755 apps/informant/dist/informant "$HOME/.local/bin/informant"
informant --version
```

`informant setup` can install the Podman packages described below; it does not install Informant.
Ensure `~/.local/bin` is on `PATH`; the user-owned install lets Informant replace its binary during an
automatic update without passwordless administrator access. Install GitHub CLI through the
distribution's package instructions and authenticate with `gh auth login`.

## Create the GitHub App

Run the interactive setup:

```bash
informant setup
```

Informant will:

1. Configure and verify the host container backend. On Apple Silicon this installs Apple's signed
   Container package. On Linux, setup offers to install Podman with `apt-get` or `dnf`, verifies that
   it is rootless with cgroups v2, and runs a bounded smoke test of the default image using CPU,
   memory, security, and writable bind-mount constraints. Podman is daemonless; Informant does not
   start a service and does not require systemd.
2. Ask whether your account or an organization should own the App.
3. Open GitHub with **Checks: read/write**, **Contents: read**, **Pull requests: read/write**, and
   webhooks disabled.
4. Receive and protect the generated private key automatically.
5. Open GitHub's installation screen so you can choose repositories.
6. Detect the installation and save its credentials without changing this machine's registered
   repositories.
7. On the first setup, ask whether to install a six-hour automatic update check.
8. Offer to start the worker.

Workers that run macOS VM jobs also need Tart and `sshpass`:

```bash
brew install openai/tools/tart cirruslabs/cli/sshpass
```

The browser steps are limited to approving creation and choosing repository access—GitHub requires
those decisions from the App owner. Informant stores everything else under `~/.config/informant`;
there are no environment variables to copy. See [GitHub App credentials](/docs/github-app) for
headless and environment-variable overrides.

Repeat `informant setup` for every additional organization this machine should serve. Each organization
gets its own private GitHub App and installation credentials.

In the repository that needs CI:

```bash
informant init
git add .informant
git commit -m "Configure Informant CI"
git push
informant hook install # supported pre-push hook; waits until the push is visible
```

`informant init` creates shared settings in `.informant/config.toml`, creates the first job in
`.informant/jobs/test.toml`, detects `owner/repository` from the `origin` Git remote, and registers it
with this machine automatically.

On macOS, or Linux with a working systemd user manager, start the worker now and automatically when
you log in:

```bash
informant startup enable
```

Use `informant startup disable` to stop the worker and remove it from login startup. Linux hosts
without a systemd user manager must not use `startup enable`; run `informant serve` in the foreground
or configure that command in the host's existing process supervisor. Podman itself remains daemonless
in either arrangement.

When enabled during setup, automatic updates run from a macOS LaunchAgent or Linux systemd user timer.
Use `informant auto-update enable` or `informant auto-update disable` to change that choice later.

Register more repositories with `informant repo add owner/repository`. Run the same registration and
serve commands on another machine to add capacity. There is no shared database to configure.
